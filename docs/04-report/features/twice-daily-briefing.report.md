# 10시·17시 일일 브리핑 완료 보고서

> **상태**: 완료
>
> **완료일**: 2026-09-21

## 결과

기후·온실가스·배출권거래제·환경 컨설팅 공고의 일일 브리핑을 한국 시간 **10:00**과 **17:00**에 각각 한 번씩 보낼 수 있도록 변경했습니다.

| 항목 | 적용 내용 |
|---|---|
| 발송 시간 | `10:00`, `17:00` KST |
| 중복 방지 | 같은 날짜라도 시간대별 발송 기록을 분리 |
| 수동 실행 | `-Mode daily -DailySlot 10:00` 또는 `17:00` 필요 |
| 자동 실행 | Codex `rfp-30`이 30분마다 확인하고 해당 시간대만 실행 |
| 메일 연결 | 다음 SMTP 테스트 메일 1건 발송 성공 |
| Windows 예약 작업 | 미등록 — Codex 자동화와 중복 운영하지 않음 |

## 변경 파일

- `rfp_tracker/notifications.py`: 복수 일일 시간대와 시간대별 중복 방지 키
- `rfp_tracker/cli.py`: `--daily-slot` 선택 및 설정 검증
- `scripts/run_notification_cycle.ps1`: 일일 시간대 전달
- `scripts/install_notification_tasks.ps1`: 필요 시 10시·17시 별도 작업 생성
- `configs/notifications*.json`: 기본 시간대를 10시·17시로 설정
- `README.md`, `.env.example`: 운영·다음 SMTP 안내 보강

## 품질 결과

33개 자동 테스트, Python 문법 검사, PowerShell 구문 검사를 모두 통과했습니다. 실제 다음 SMTP 테스트는 서버 기준 `sent=1`로 완료됐으며, 이후 실제 공고 브리핑은 SQLite 발송 기록으로 중복을 막습니다.

## 운영 시 유의점

테스트 메일의 수신함 도착을 먼저 확인하고, 첫 며칠간은 10시·17시 브리핑의 `환경` 후보를 사람이 검토하세요. Codex 자동화가 활성화된 동안에는 Windows 작업 스케줄러를 별도로 등록하지 않는 것을 권장합니다.
